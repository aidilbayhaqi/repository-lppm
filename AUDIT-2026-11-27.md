## 1. BLOCKER — Secret production di git history publik

`.env.docker` pernah di-commit lalu dihapus. Penghapusan **tidak** menghapus isinya dari history.

| Item | Detail |
|---|---|
| Commit menambahkan | `0bc460b`, `aedc51c` |
| Commit menghapus | `591af99` |
| Status HEAD | Bersih — file tidak ada |
| Status history | **Masih bisa dibaca** via `git show aedc51c:.env.docker` |

Isi terekspos (nilai disensor):

- `APP_KEY`
- `DB_PASSWORD`
- `MYSQL_ROOT_PASSWORD`
- `MAIL_PASSWORD`
- `REDIS_PASSWORD`

**Kenapa kritis:** `APP_KEY` adalah kunci enkripsi Laravel. Dengan kunci itu, penyerang bisa mendekripsi cookie terenkripsi, memalsukan session, dan mendekripsi kolom terenkripsi. Repo publik — siapa pun bisa `git clone` dan melihatnya kapan saja.

**Wajib sebelum production:**

1. Rotasi semua kredensial di atas — anggap sudah dicuri
2. `git filter-repo --path .env.docker --invert-paths` (atau BFG)
3. Force-push semua branch + tag
4. Minta kolaborator re-clone (history lokal mereka masih menyimpan)
5. Aktifkan secret scanning (GitHub Advanced Security / gitleaks di CI)

**Catatan:** `.gitignore` sekarang sudah benar, working tree bersih. Masalahnya murni history — tapi history itu permanen sampai di-purge.

## 2. Temuan berdasarkan severity

### TINGGI

**2.1 — CVE-2026-133754 hidup di `symfony/routing v8.1.11`**

Ditemukan lewat `composer audit`. Fix tersedia di `8.1.12`.

*Reachability:* saya cek seluruh `routes/` dan `app/` — **nol** pemakaian `domain()` untuk route dinamis, dan `UrlGenerator` tidak dipakai di jalur rawan. Artinya **tidak exploitable di repo ini**, tapi tetap wajib bump. Jangan andalkan "tidak terjangkau" sebagai alasan menunda.

**2.2 — Pint gagal 63 file, dan CI tidak pernah menjalankan Pint**

```
$ php vendor/bin/pint --test --format=json | grep -o '"path"' | wc -l
63
```

Diverifikasi dua kali. Masalahnya bukan formatting-nya, tapi **tidak ada gate**: `.github/workflows/ci.yml` tidak punya langkah Pint. Dokumentasi menyiratkan Pint lulus — tidak.

Konsekuensi: gaya kode akan terus melenceng karena tidak ada yang menahannya.

**2.3 — Nol static analysis**

Tidak ada PHPStan/Larastan di `composer.json` maupun CI. Untuk basis kode 7040 LOC dengan workflow penerbitan yang kompleks, ini celah nyata — bug tipe dan null-reference tidak akan tertangkap sampai runtime. Larastan level 5 akan menangkap banyak tanpa biaya tinggi.

### MEDIUM

**2.4 — JS mematikan validasi yang server minta**

`resources/js/feedback.js:4`:

```js
document.querySelectorAll('form[data-requires-notes="true"] textarea[name="notes"]')
  .forEach(input => { input.required = false; });
```

Tapi `app/Http/Requests/WorkflowRequest.php:19` mewajibkan `notes` untuk aksi `revision`, `reject`, `reopen`, `unpublish`, `archive`.

Kontradiksi: server bilang wajib, klien bilang opsional. User mengisi form, submit, lalu kena 422 bolak-balik tanpa peringatan di depan. Pengalaman buruk sekaligus menyembunyikan aturan bisnis.

**2.5 — Heading order melompat**

`resources/views/admin/import/index.blade.php`: urutan heading `1, 3, 3, 3, 2, 2`.

Screen reader membacakan hierarki yang lompat naik lalu terbalik. Perbaikan sepele: tiga `<h3>` jadi `<h2>`.

**2.6 — 117 warna hex hardcoded, 3 stylesheet tanpa design token**

| File | Hex | Token |
|---|---|---|
| `repository.css` | 116 | 46 |
| `journal-experience.css` | 24 | 8 |
| `guided-submission.css` | 1 | **0** |
| `experience.css` | 1 | **0** |
| `app.css` | 0 | **0** |

`guided-submission.css` dan `experience.css` praktis light-only — tidak punya token sama sekali, jadi tidak bisa beradaptasi ke dark mode. Kontras teks di dark theme berisiko gagal WCAG.

**2.7 — Error form tidak terhubung ke input**

`resources/views/components/input-error.blade.php` dipakai **22 kali**, tapi tidak punya `role="alert"`, `aria-invalid`, atau `aria-describedby`. Pengguna screen reader tidak diberi tahu field mana yang salah dan kenapa.

Ironisnya, JS di jalur lain sudah benar — jadi ini soal konsistensi, bukan ketidaktahuan.

**2.8 — Artefak mati masih tracked**

- `postcss.config.js.bak` — file backup ter-commit
- `tailwind.config.js` — **tidak pernah dimuat** (Tailwind 4 CSS-first, tidak ada `@config` di `app.css`), jadi semua isinya inert
- `layouts/navigation.blade.php` — 100 baris Breeze default, **nol referensi**, label masih bahasa Inggris + logo Laravel
- `x-modal` — **0 pemakaian**
- `x-nav-link`, `x-responsive-nav-link`, `x-application-logo`, `x-dropdown` — sisa scaffolding

`tailwind.config.js` paling menipu: developer akan mengeditnya dan bingung kenapa tidak berpengaruh.

### RENDAH

- `storage/framework/faculty-updater.lock` tracked, 0 byte — artefak runtime yang tidak di-ignore
- Tidak ada coverage config (pcov/xdebug) di CI — tidak tahu test mana yang mati
- `symfony/routing` pin belum diperbarui di `composer.lock`

## 3. Yang sudah bagus — dan ini serius

### 3.1 Test suite benar-benar jalan

```
223 test · 1204 assertion · 100% lulus · 15.7 detik
```

Saya jalankan sendiri setelah install PHP 8.4.28 + `composer install` + `npm run build`. Bukan klaim dokumen.

LOC: **app 7040** vs **test 4152** — rasio test terhadap kode sehat. Banyak proyek institusional punya test suite 200 baris yang tidak menguji apa pun.

### 3.2 Keamanan autentikasi paling kuat di proyek ini

`app/Http/Middleware/SecureSession.php` mengikat session ke `auth_version`. Ganti password = semua session lama mati otomatis. Ditambah absolute lifetime — session tidak bisa diperpanjang tanpa batas.

`app/Services/Totp.php` + `app/Http/Controllers/Auth/MfaController.php`: MFA TOTP **ditulis sendiri, tanpa library eksternal**, dan benar di tiga hal yang sering salah:

- **Replay guard** lewat `mfa_last_step` — kode TOTP yang sama tidak bisa dipakai dua kali
- **Recovery code** disimpan **hashed**, single-use
- **Akun privileged tidak bisa menonaktifkan MFA sendiri**
- `lockForUpdate` mencegah race condition saat verifikasi

Kombinasi ini jarang ada bahkan di aplikasi komersial.

### 3.3 Authorisasi berlapis dan sadar konflik kepentingan

`app/Policies/WorkPolicy.php` menolak penulis memverifikasi karyanya sendiri. Ini kontrol yang tepat untuk repositori akademik — mencegah dosen meloloskan publikasinya sendiri.

Ditambah gate verified-email dan staff scoping. `routes/web.php` disiplin: `auth` + `active` + `verified` + throttle di 15 titik, gate `can:` untuk area admin.

### 3.4 Rate limiting terstruktur

Tiga limiter di `app/Providers/AppServiceProvider.php`:

- `mutations` — operasi tulis
- `login` — brute force
- `auth-requests` — reset password & verifikasi

Dipakai 15 kali di route. Bukan throttle asal-asalan.

### 3.5 Pipeline dokumen aman

`app/Services/MalwareScanner.php` **fail-closed**: scanner mati = upload ditolak, bukan diterima. Kebanyakan implementasi salah di sini (fail-open = celah besar).

`app/Http/Requests/DocumentRequest.php` memvalidasi ganda: `mimes:pdf` **dan** `mimetypes:application/pdf`, batas `max:20480`. Pemeriksaan ekstensi saja bisa diakali; MIME sniffing juga bisa; keduanya sekaligus jauh lebih sulit.

`DocumentService::replace()` memanggil ulang otorisasi **di dalam lock** — bukan sebelum lock. Detail kecil yang menghilangkan jendela TOCTOU/IDOR.

### 3.6 Disiplin transaksi

**28 pemanggilan `DB::transaction` tersebar di 19 file** — service layer, controller, command. Workflow penerbitan (`PublicationWorkflow`, `PublishingService`, `RegistrationApprovalService`, `ImportService`) semuanya transaksional.

### 3.7 `AuditLog` benar-benar append-only

Melempar `LogicException` kalau ada yang mencoba `update()` atau `delete()`. Bukan sekadar konvensi — ditegakkan di level model. Sesuai kebutuhan jejak audit institusi.

### 3.8 Job queue dengan proteksi lengkap

`app/Jobs/PublishPublication.php` mengimplementasikan `ShouldBeUnique` + `uniqueId()`, `$tries = 3`, `$timeout = 60`, `backoff()` bertahap, dan handler `failed()`. Semua yang dibutuhkan untuk job idempoten ada.

### 3.9 Frontend bersih dari XSS

Dari 79 view: **0** penggunaan `{!!` (unencoded output). **0** form tanpa `@csrf`. **0** `innerHTML`/`document.write` di JS.

Ditambah skip-link, `prefers-reduced-motion`, dan `aria-hidden` pada ikon dekoratif.

### 3.10 `repository:production-check` nyata

Saya jalankan — 18 pemeriksaan, fail-closed benar (gagal di env local sebagaimana mestinya). Bukan cek kosong yang selalu hijau.

### 3.11 Scheduler aktif

Dua command terjadwal di `routes/console.php` dengan `onOneServer()` + `withoutOverlapping()`:

- `repository:recover-publishing` — tiap 5 menit
- `repository:monitor-security` — tiap 5 menit, hanya di production

Kedua proteksi itu penting untuk topologi dua instance: mencegah command jalan ganda bersamaan.

### 3.12 Docker production-grade

Multi-stage build, non-root `www-data`, opcache aktif, ekstensi redis dipin. `compose.production.yml` memakai `:?` untuk fail-fast dan **Docker secrets**, bukan env plaintext. Dua instance app + Nginx `least_conn` + Redis + MySQL 8.4 + ClamAV + worker + scheduler.

*Batas:* topologi satu host, bukan HA lintas mesin. Untuk skala LPPM ini memadai.

### 3.13 CI disiplin

Pinned action SHA (supply chain), SBOM digenerate, matriks dual-DB (SQLite lokal + MySQL 8.4 production). Yang kurang hanya Pint, static analysis, dan coverage.

### 3.14 Dokumentasi jujur

`docs/VALIDATION.md` mengakui sendiri batas kesiapannya. Semua dokumentasi konsisten mengulang "never `migrate:fresh`". Saya scan seluruh migrasi — tidak ada `dropTable`/`dropColumn` destruktif, dan tidak ada `migrate:fresh` di `app/`, `tools/`, `deploy/`, `docs/`.

Dokumentasi yang jujur tentang kelemahan sendiri adalah tanda tim yang serius.

### 3.15 Skema database sehat

35 migrasi. 25 file punya index eksplisit. Foreign key constraints konsisten di tabel pivot dan relasi utama. Migrasi terakhir (`harden_sessions_concurrency_and_query_indexes`) menunjukkan tuning query yang sadar performa.

### 3.16 Query bersih

Eager loading benar di seluruh controller yang saya periksa — `RepositoryController` (3 model sekaligus), `Admin/DashboardController`, `RegistrationApprovalController`. Dashboard saya audit khusus untuk N+1: **tidak ada**, `with('penulis:id,nama')` dipasangkan benar dengan `$work->penulis->pluck()` di view.

Tidak ada query tak terbatas yang berbahaya — empat pemanggilan `get()` tanpa paginasi semuanya wajar (dokumen per-karya, daftar admin kecil).

### 3.17 Error handling disiplin

16 `try/catch`, nol di antaranya `catch` kosong (menelan error diam-diam). 8 menangkap `\Throwable` — tepat untuk jalur yang perlu menangani semua kegagalan.

## 5. Penilaian kesiapan production

### Sudah production-grade

Skema database, transaksi, otorisasi, MFA, session hardening, Docker, CI, dokumentasi, test suite, pipeline dokumen, query hygiene.

### Belum production-ready karena

1. **Secret di history publik** — blocker keras, di luar pertimbangan kualitas kode
2. **Tidak ada gate format & static analysis** — utang kode akan menumpuk tanpa terlihat
3. **CVE belum di-bump** — walau tidak terjangkau, ini utang keamanan
4. **Nol verifikasi runtime produksi** — SMTP, Redis, ClamAV, restore backup semuanya belum diuji dengan infrastruktur nyata

### Jalur ke production

Kerjakan **P0** (setengah hari) → skor naik ke **~8.0**. Kerjakan **P1** (2–3 hari) → **~8.7**. Kerjakan **P2** sebelum go-live → **~9.2**.

Item P0 hampir seluruhnya operasional (rotasi + purge + koordinasi re-clone), bukan perbaikan kode. Kode aplikasinya sendiri sudah dalam kondisi baik.

### Rekomendasi jangka pendek

**Minggu ini:** staging. Jalankan P2 di sana untuk mengumpulkan bukti runtime.

**Production:** setelah P0 selesai dan P2 lulus. Jangan lompat ke production dengan `APP_KEY` lama yang sudah publik.

## 6. Catatan metode

Detail yang saya perlukan untuk menilai dengan jujur:

- Docker tidak terjangkau dari WSL (integrasi mati) → PHP 8.4.28 dipasang native via `ppa:ondrej/php`
- `composer` wrapper di `/mnt/d/COMPOSER/composer` hanya mencetak isi, tidak menjalankan → `composer.phar` diambil langsung
- Test awal gagal karena asset Vite belum di-build → `npm ci --ignore-scripts` + `npm run build`, lalu ulang
- Empat subagent audit paralel dijalankan; temuannya saya verifikasi ulang satu per satu. Satu klaim ditolak: `layouts/app.blade.php` disebut dead dan punya `$slot` undefined — ternyata dipakai `profile/edit.blade.php` lewat `x-app-layout` dan `$slot` valid
- **Tidak ada file repo yang diubah.** Hanya `.env`, `database.sqlite`, `vendor/`, `node_modules/`, `public/build/` — artefak lokal yang tidak masuk git

**Tidak bisa diverifikasi tanpa akses server:** apakah kredensial di deployment live sudah dirotasi. Karena history bersifat publik, rekomendasi rotasi berlaku mutlak.
